# 接続コードの品質改善

起点は PR #1 の `0390656`。開始時点では元の作業ディレクトリと専用コピーの両方が clean。

## 方針

- 認証の通信失敗、HTTP 拒否、429、サーバー応答を型で区別する。キャンセルはキャンセルとして伝える。
- `LinkState` を接続状態の正本にし、外部から phase を変更できなくする。
- 認証と WebSocket は Cookie を共有するローカル通信境界へ分離する。Controller には進行管理と表示を残す。
- PeerLink の状態は MainActor が所有する。RTC の delegate とデコーダは非同期受け口に残し、イベントを MainActor へ直列配送する。クラス全体を無条件に actor 化して delegate を直呼びさせる方法は使わない。
- 入力モデル、描画統計の重複、実行経路から使われない RTP 再構成と HID 分岐を整理する。汎用 DI コンテナや将来用の階層は作らない。
- 実通信境界に小さい protocol を置き、正常接続、再接続、古い callback と認証エラーを再現する。既存 wire format と映像の FIFO・キーフレーム回復を維持する。

署名・Apple ログイン・VPN・OS の設定変更は行わない。実機とローカル Simulator の未検証は残す。


## 実装と途中検証

- 状態と出力プロパティを外部から変更できなくし、各接続の資源を Attempt でまとめた。
- MainActor の PeerLink と、値イベントだけを渡す RTC delegate adapter に分けた。映像は FIFO のまま。
- 認証の HTTP/通信境界テスト、正常接続・再接続・遅延 callback・入力状態の回帰を追加。
- 未使用 RTP depacketizer とその専用テストを削除。RTP は WebRTC が再構成する。H.264 Annex-B/AVCC と復帰テストは維持する。
- HID は実際に使う reliable ordered の 1 チャネルへ統一。対象 firmware の webrtc.go でラベルごとに独立した受付を確認した。
- CoreMedia の処理失敗は型と診断カウンタに残し、意図した破棄と分ける。

最終チェックと独立レビューの結果は PR 本文と完了報告へ記載する。


## 検証記録

- Core 30 テストと、認証境界・実 WebRTC の native 12 テストが成功。
- iOS の正常接続、再接続、遅延 callback、エラー分類、計測、描画診断、所有者解放のテストを追加。ローカルはコンパイル確認、実行は CI で確認する。
- 独立レビューの残存指摘（設計文書のチャネル数、不要な認証イベント）を修正し、再確認済み。
- 既存の WebRTC field-trial 初期化 API の非推奨警告は残る。ピン留め SDK の Objective-C 公開 API に置換先が無く、機能を外して警告を隠す変更はしない。
- 実機は Team 未設定と本人のローカル認証入力が必要。CoreSimulator は既存のバージョン不整合のまま。署名、インストール、OS/VPN 設定は変更していない。
