# 遅延の測り方

ガラスからガラスの目標は約 50 ms です。内訳は [DESIGN.md](./DESIGN.md) の予算表です。ここは、実機が手元にある人が区間を分ける手順です。自動の画素読み取りはホットパスに載せません。`AVSampleBufferDisplayLayer` から画素は戻ってきません。

## 画面の時計

`tools/latency/clock.html` を Windows PC で開きます。インストールは不要で、`file://` のまま使えます。クリックすると全画面になります。

ページはローカル時刻と、`Date.now()` の下位 20 ビット（`0xFFFFF` マスク）を出します。下の 24 セルは Swift の `LatencyBarcode` と同じ並びです。

1. 先頭セルは黒、次は白である。
2. 続く 20 セルは、ミリ秒の下位 20 ビットを上位ビットから並べる。黒が 1、白が 0 である。
3. その次は 20 ビットの XOR パリティである。
4. 末尾は白である。

iPhone のオーバーレイ「時計」は、同じ UNIX ミリ秒の下位 6 桁（100 万での剰余）です。2 つの画面を 1 枚の写真に収めると、桁の差がガラスからガラスの候補になります。Windows と iPhone の時計がずれていると、そのずれがそのまま載ります。桁を読む前に、同じ NTP に揃えるか、次の F12 法を主測定にしてください。

## F12 で往復を見る

アプリの F12 は、ローカルの表示を約 80 ms 点灯させ、同時に HID の F12 を送ります。`clock.html` は F12 でページを約 500 ms 白くします。

ハイスピードカメラを iPhone の画面だけに向けます。点灯の始まりから、映像の中のページが白くなるまでが、入力、キャプチャ、エンコード、ネットワーク、デコード、表示の往復です。片道のガラスからガラスではありません。キーを離す時刻は使いません。白さは 500 ms あるので、フレームを後から追えます。

ブラウザの F12 メニューが邪魔するときは、ページを全画面にしてからアプリの F12 ボタンを使います。HHKB の F12 を使う場合は、iPhone がキーを食わないことを先に確認します。

## 映像だけを分配器で見る

HDMI 分配器の一方を Windows のモニタ、もう一方を JetKVM に入れます。カメラをモニタと iPhone の両方に向け、時計の桁かバーコードの変化を比べます。これは入力を含まない映像遅延です。

同じ LAN で測った映像遅延から、オーバーレイの RTT/2 を引いた残りが、キャプチャ、エンコード、デコード、表示の上限です。enqueue のミリ秒は、デコードが終わったあとにレイヤへ渡す時間だけで、ジッタバッファを含みません。ジッタバッファは WebRTC の中に残り、オーバーレイには分離して出ません。

## 入力だけを見る

分配器のモニタ（JetKVM を通さない側）と、HHKB のキーを同じフレームに入れます。キーが底についてから、モニタのページが白くなるまでが USB HID と OS の入力遅延です。iPhone の映像遅延はここへ混ぜません。

## ネットワーク

オーバーレイの RTT/2 は、WebRTC 統計の `candidate-pair` で `state == succeeded` の `currentRoundTripTime` を半分にしたものです。経路が `Tailscale host` でも、Tailscale の中身が DERP ならこの値は大きくなります。そのときはアプリの ICE ではなく、`tailscale status` で直接経路かを見ます。

オフィス LAN と宅外で、同じ時計手順の往復を 1 回ずつ残します。クラウド UI の TURN をアプリは使いません。宅外がなお遅いときは、DERP とエンコーダの固定ビットレートと残ったジッタバッファのどれかを、RTT/2 と破棄フレームと画質で分けます。

## バーコードの検査

`LatencyBarcode` の生成と復号は `swift test` に含まれます。セルの輝度が 128 未満を黒とします。実機のカメラ画像から自動復号するツールは、表示レイヤが画素を返さないので今回は作りません。写真のセルを数えるときは、先頭が黒、次が白、末尾が白、パリティが合うことだけを見ます。
